# 사내 비품관리시스템 (Asset Management System)

전자정부 표준프레임워크(eGovFrame) 기반의 사내 비품 대여/반납 관리 시스템입니다.
직원은 비품을 조회하고 대여를 신청합니다.
관리자는 대여/연장 승인, 비품 등록, 회원 가입 승인, 고장 신고 처리 등을 담당합니다.

기존에 엑셀/수기로 관리되던 사내 비품 대여 현황을 웹 기반으로 바꾸는 것이 목표입니다.
QR 코드로 반납을 처리하고, 신고(고장 등) 접수도 처리 단계를 기록해서
지금 어느 단계인지 언제든 추적할 수 있도록 만들었습니다.

## 주요 기능

- **사용자**
  - 회원가입 / 로그인 (비밀번호는 암호화해서 저장, 로그인 상태는 세션처리로 서버가 기억)
  - 비품 목록 조회(카테고리별 필터 + 페이징) 및 대여 신청
  - 대여 연장 신청 (희망 반납일/사유 입력 → 관리자 승인 전까지는 기존 반납일 유지)
  - QR 코드를 통한 반납 처리 (비품 부착 QR 스캔 → 본인 확인 후 반납/연장/신고 중 선택)
  - 비품 문제(고장 등) 신고 등록 (사진 첨부 가능)
  - 내 대여 현황 조회 (반납 완료/신고종료 건은 목록에서 자동 제외)
  - 내 정보 조회 및 회원 탈퇴 (관리자 계정은 탈퇴할 수 없음)
- **관리자**
  - 회원가입 승인 / 반려 처리
  - 비품 등록·수정·삭제 및 카테고리 관리 (사용 이력이 있으면 삭제 시 보호)
  - 비품별 QR 코드 발급 (ZXing 기반 PNG 생성, 인쇄용 화면 제공)
  - 대여 / 연장 신청 승인·반려
  - 신고 접수 처리 (접수 → 고장확인 → 수리중 → 수리완료 순서로 처리, 또는 반려)
  - 반납/신고종료 시 대여 기록을 삭제하지 않고 상태 변경으로 이력 보존

## 핵심 흐름

### 1. 로그인 확인 / 권한 확인
- `LoginCheckInterceptor`라는 코드가 화면 요청이 들어올 때마다 먼저 실행되어,
  로그인이 되어 있는지부터 확인합니다.
- 로그인이 확인된 뒤에는 `AdminCheckInterceptor`가 한 번 더 실행되어,
  관리자만 볼 수 있는 화면인지 확인합니다.
- 로그인을 안 한 상태로 로그인이 필요한 화면에 들어가려고 하면,
  - 원래 가려던 화면 주소를 잠깐 기억해두고 로그인 화면으로 보냅니다.
  - 로그인에 성공하면 처음에 가려던 화면으로 자동으로 이동시켜 줍니다.
- 회원 상태(`users.use_yn`)는 아래 네 가지로 나뉘고, 로그인 실패 시 상태에 맞는 안내 메시지를 보여줍니다.
  - `Y`: 정상 이용 가능 / `P`: 가입 승인 대기 중 / `R`: 가입 반려됨 / `N`: 탈퇴함

### 2. QR 코드로 반납하는 흐름
1. 관리자가 비품마다 QR 코드를 만들어 발급합니다. (비품에 부착해서 사용)
2. 사용자가 이 QR을 스캔하면, 그 비품이 지금 어떤 상태인지에 따라 다른 화면으로 이동합니다.
   - 고장 신고된 비품: 로그인 여부와 상관없이 안내 문구를 보여주고 메인 화면으로 보냅니다.
   - 대여 중인 비품: 먼저 로그인을 확인한 뒤, 스캔한 사람이 실제로 이 비품을 빌린
     본인이 맞는지 한 번 더 확인하는 선택 화면으로 이동합니다.
   - 대여 가능한 비품: 이 비품이 미리 선택된 상태로 대여 신청 화면으로 이동합니다.
3. 본인 확인이 끝나면 반납, 연장 신청, 문제 신고 중 하나를 골라 진행할 수 있습니다.

### 3. 대여 신청이 처리되는 단계
```
승인대기 → 승인(대여중) → 반납완료
                       └→ 신고로 종료됨
     └→ 반려
```
- 대여 신청도, 연장 신청도 관리자가 승인하기 전까지는 아무 것도 바뀌지 않습니다.
  비품 상태나 반납 예정일 같은 실제 정보는 승인이 나야 반영됩니다.
- 연장 신청 역시 마찬가지로, 승인이 나야 반납 예정일이 실제로 변경됩니다.

### 4. 고장 신고가 처리되는 단계
```
접수됨 → 고장 확인됨 → 수리중 → 수리완료
     └→ 반려
```
- 신고가 접수되는 즉시 그 비품은 "고장" 상태로 바뀌어, 다른 사람이 빌릴 수 없게 됩니다.
- 관리자가 "고장 확인" 처리를 하면, 그 비품을 빌려간 대여 건은 자동으로 종료 처리됩니다.
- 관리자가 "수리완료" 처리를 하면, 비품은 다시 대여 가능한 상태로 돌아옵니다.
- 관리자가 신고를 반려하면, 대여 건은 그대로 유지되고 비품 상태만 "대여중"으로 되돌아갑니다.

## 기술 스택

| 구분 | 내용 |
|---|---|
| Language | Java 17 |
| Framework | eGovFrame 4.3.1, Spring MVC 5.3 |
| Persistence | MyBatis |
| DB | MySQL |
| View | JSP, JSTL, Bootstrap, jQuery |
| Security | Spring Security Crypto (BCrypt로 비밀번호 암호화), 로그인/권한 확인은 직접 만든 코드로 처리 |
| QR 코드 | ZXing (QR 이미지 생성 라이브러리) |
| Build | Maven |

## 데이터베이스 구조

| 테이블 | 설명 | 주요 컬럼 |
|---|---|---|
| `users` | 사용자 계정 | `role`(관리자/일반), `use_yn`(가입 상태), `employee_number`(사원번호) |
| `CATEGORY` | 비품 카테고리 목록 | `category_name`(카테고리 이름, 중복 불가) |
| `EQUIPMENT` | 비품 | `status`(대여가능/대여중/고장), `category_id`(카테고리 연결), `qr_image_path`(QR 이미지 경로) |
| `RENTAL` | 대여/연장 신청 | `request_status`(대여 처리 상태), `extend_status`(연장 처리 상태) |
| `REPORT` | 비품 문제 신고 | `status`(신고 처리 상태), `issue_type`(신고 유형), `image_path`(첨부 이미지) |

- 대여 기록은 반납/신고종료 시에도 지우지 않고, 상태값만 바꿔서 이력을 남깁니다.
- 관리자 계정은 따로 만드는 화면이 없습니다.
  일반 회원가입을 한 뒤, DB에서 직접 관리자 권한으로 바꿔줘야 합니다.
  (방법은 `asset_schema.sql` 파일 안 주석에 적어뒀습니다.)

## 프로젝트 구조

```
src/main/java/egovframework/asset
├── cmmn/       # 공통 설정, 로그인/관리자 인터셉터, 예외 처리, QR 유틸, 페이징
├── equipment/  # 비품 등록/조회, 대여·연장·신고 화면 라우팅, QR 발급/반납 처리
├── rental/     # 대여/연장 신청 및 승인 서비스
├── report/     # 비품 문제 신고 및 처리 상태 관리
└── user/       # 회원가입, 로그인, 관리자 승인

src/main/webapp/WEB-INF/jsp/egovframework/asset
├── admin/      # 관리자 화면 (비품/카테고리 관리, QR 인쇄, 승인 목록, 신고 처리)
├── equipment/  # 대여/연장/신고/QR 반납 화면
└── user/       # 로그인/회원가입/내정보

src/main/resources/db
├── db.properties.example  # DB 접속 정보 템플릿
└── asset_schema.sql       # DB 스키마 + 관리자 계정 생성 방법 주석
```
